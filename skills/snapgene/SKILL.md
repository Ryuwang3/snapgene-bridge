# SnapGene Bridge

`snapgene-bridge` (short alias `sgb`) designs primers locally and asks a
SnapGene node for the official numbers. Every command prints one JSON object;
read it, never scrape stderr.

## Procedure

1. **Check the node.**

   ```bash
   snapgene-bridge status
   ```

   Continue only if `"ready": true`. Otherwise act on `node.problems` or
   `node.error`:

   - SnapGene is open on the node: ask the user to close it.
   - Not deployed, or the version differs: run `snapgene-bridge deploy`.
   - SSH fails: ask the user to check `ssh <host>`.

   If no node is configured and the user only wants a rough answer, every
   design or check command accepts `--offline`. Say clearly that the
   offline values are estimates.

2. **Inspect the template before choosing coordinates.**

   ```bash
   snapgene-bridge validate FILE
   ```

   This lists length, topology, and features with 1-based `a..b` locations.
   Prefer `--feature NAME` over typed coordinates when a feature exists.

3. **Pick the command.**

   - Primers already exist and you need SnapGene's Tm and binding sites:

     ```bash
     snapgene-bridge check FILE --primer NAME=SEQ
     ```

     Repeat `--primer` for each primer, or pass `--primers FILE`.

   - Subcloning, where primers sit exactly on the insert ends, optionally
     with 5' tails such as restriction sites or overlaps:

     ```bash
     snapgene-bridge clone FILE --feature NAME --tail-f SEQ --tail-r SEQ
     ```

     Instead of `--feature`, you can give `--region a..b --strand +|-`.

   - Amplifying a region that must lie fully inside the product (screening,
     genotyping, or diagnostic PCR):

     ```bash
     snapgene-bridge pcr FILE --feature NAME
     ```

     Instead of `--feature`, you can give `--target a..b`. Add
     `--product-size MIN-MAX` to bound the product length.

   - Useful options for `clone` and `pcr`: `--target-tm` (default 60),
     `--max-dtm` (default 2), `--length MIN-MAX`, `--offtarget-max-tm`
     (default 45), and `--name PREFIX`.

4. **Write results to new paths only.** Use `--output NEW.dna` (generated by
   SnapGene itself) and `--order NEW.tsv`. Add `--force` only when the user
   explicitly asks to overwrite.

5. **Report the result.** Include:

   - Both primer sequences, 5'->3'.
   - The SnapGene Tm of each primer and the Tm difference.
   - The annealed length per SnapGene, from `site.annealed_length`.
   - Off-target sites, with their Tm.
   - Product length.
   - Any `warnings` and `checks.warnings`.
   - The output and order-sheet paths.

## Rules for numbers

- Quote `tm_standard` with every Tm.
  - `snapgene-<version>` means SnapGene computed the value.
  - `estimate:nn` is a local estimate. Never call an estimate "SnapGene's Tm".
- SnapGene's Tm covers only the annealed bases (no 5' tails) at 50 mM Na+ and
  no Mg2+, and it is an integer.
  - For Phusion or Q5 annealing, SnapGene suggests about 6-12 C above its Tm.
  - For a vendor-specific annealing temperature, point the user to that
    vendor's calculator.
- Coordinates in commands are 1-based inclusive (`1626..2486`, the same as
  SnapGene's display).
  - The JSON gives `start`/`end` as 0-based half-open, plus a `location`
    string.
  - Show `location` to the user.
- `imported: false` means SnapGene found no site with a Tm of at least
  40 C. Report that the primer does not bind under SnapGene's default
  hybridization parameters.

## Errors

| `error.code` | What to do |
|---|---|
| `node_not_configured` | Ask for the node SSH alias. Then run `snapgene-bridge init --host ALIAS` and `snapgene-bridge deploy`, or use `--offline`. |
| `node_unreachable` | SSH failed; show `details.stderr` and ask the user to check connectivity. |
| `node_error` | Usually not deployed or outdated; run `snapgene-bridge deploy`. |
| `snapgene_busy` | Ask the user to close SnapGene on the node. |
| `snapgene_timeout` | A dialog blocked SnapGene. Show `details.dialog_text` and ask the user to open SnapGene on the node once and dismiss the dialog. |
| `no_valid_design` | Read `details` and suggest which limit to relax: length, Tm difference, or off-target limit. |

## Boundaries

- Never automate the SnapGene GUI, inject into it, or reverse-engineer it.
  The supported path is the official command line driven by this tool.
- Never upload sequences to third-party services unless the user explicitly
  asks.
- Do not kill SnapGene processes or change settings on the node yourself.
- After a SnapGene upgrade, run `snapgene-bridge selftest` before trusting new
  results.
- Not built yet: Gibson or HiFi overlap planning, Golden Gate, and
  sequencing-primer tiling. For a simple two-fragment overlap design, `clone`
  with homology arms as `--tail-f` and `--tail-r` works, but say that the
  overlap Tm is not checked.
